## Status: 10 October 2026

Fixed in source on the v0.0.35 line before any build used it.

## Symptom

The world flora integration test stopped with "File exists" on the region's `collision-per_instance` folder
when a flora overlay went over its clipnode reserve and the routed-hull fallback ran the overlay again.

## Where

`tools/prepare_world_flora.py`, `_hull_fallback`.

## How it happened

Two changes met in one merge: the fallback (BUILD-ROUTED-FLORA-RESERVE-33) removes the failed try's
candidate folders before it retries with chains, using the folder recorded in the packing report; the
reproducible-output repair (BUILD-OUTPUTS-NOT-REPRODUCIBLE-33) had changed that record to a name relative to
the region folder. The fallback looked the name up relative to the working folder, removed nothing, and the
retry could not create its folder again.

## Why it was not caught

Each change was tested on its own branch; the combination only existed after the merge.

## Reproduction

tests/test_world_flora_integration.py `test_adaptive_actual_candidates_choose_default_or_aggregate_and_preserve_failures`
on the merged tree, before the repair.

## Repair

The fallback resolves a recorded candidate folder relative to the region folder (an absolute one is used as
it is).

## Verification

The integration test passes; the full gate on the merged head.

## Prevention

Every merge into the release line is gated as a whole before anything is built from it.
