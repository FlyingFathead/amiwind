## Status: 9 October 2026

Fixed in source on v0.0.33-miniwind2, not shipped at the time of writing.

Provenance: found in the AmiWind "MiniWind" Playtester Build run mw2-033a, version 0.0.33-dev1, source
v0.0.33-miniwind2 5226fcf, CHIM 0.1.0, world format 0.5.

## Symptom

The CHIM stage stopped: "OSError: /tmp/amiwind-zone-.../libchimzone.so: failed to map segment from shared
object".

## Where

`tools/chim/zone_sim.py`, `require_zone_walk`: the zone walk gate (CHIM-CHUNK-LOAD-FAIL-33) compiles the
engine's zone allocator for the host and loads it with ctypes, from a folder made by `tempfile.mkdtemp()`.

## How it happened

The build container mounts `/tmp` as a tmpfs, which Docker mounts noexec by default; hardened hosts do the
same. A shared object cannot be mapped from a noexec mount.

## Why it was not caught

The gate's tests and the CHIM builder's own runs had an executable `/tmp`.

## Reproduction

Run the chim stage in a container started with `--tmpfs /tmp`.

## Repair

The library is built and loaded under the CHIM output's `work` folder (the build's own storage) and removed
afterwards.

## Verification

`test_gate_builds_its_library_under_the_output_folder_not_tmp` (tests/test_chim_zone_sim.py); the next
MiniWind build's chim stage.

## Prevention

Build-time helpers that load compiled code use the build's output folder, never the system temp folder.
