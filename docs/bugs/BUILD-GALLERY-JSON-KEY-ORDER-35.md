## Status: 10 October 2026

Fixed in source on the v0.0.35 line, not shipped.

## Symptom

Two from-scratch builds of the same commit (`..._full_901f8e9`, `..._full-try5_901f8e9`) wrote different npc-gallery
outputs: 3,460 of 10,669 files (`gallery/m*.json`, `gallery-audit.json`). The contents are the same; only the key
order differs.

## Where

`tools/gallery_cache.py` `materialize`, `tools/prepare_gallery.py` (model receipts, `gallery-audit.json`).

## How it happened

A model converted fresh writes its result in insertion order; a model taken from the gallery cache comes from
`entry.json`, stored with sorted keys. Which models come from the cache differs between builds.

## Why it was not caught

The byte-identical checks compared runs with the same cache state.

## Reproduction

Two builds with different gallery cache contents.

## Repair

Every gallery JSON writer sorts its keys. npc-gallery's outputs change once.

## Verification

`tests/test_stage_key_coverage.py` `GalleryBytesTests`: a cached and a fresh result write the same bytes; every gallery
JSON writer passes `sort_keys=True`.

## Prevention

The from-scratch payload compare (build_audit --compare) lists such files; a resume reports which stage's outputs
differ (output_differences).
