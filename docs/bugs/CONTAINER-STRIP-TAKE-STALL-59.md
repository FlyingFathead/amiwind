_Last updated with AmiWind v0.0.59-dev6 (3 November 2026)._

## Status: 3 November 2026

Fixed in v0.0.59-dev6 by the per-area tables for containers.

## Symptom

Opening the container strip, taking an item or putting one back held the game for a noticeable time, in Arrille's
Tradehouse.

## Where

The container strip's reads of the container data, owners, item records and item pictures.

## How it happened

Each of those reads searched an island-wide file during play. See
[TRADEHOUSE-LONG-FRAME-59](TRADEHOUSE-LONG-FRAME-59.md) for the buffer cost of such a search.

## Why it was not caught

The time of the strip's reads was not measured on the emulator before this report.

## Reproduction

In Arrille's Tradehouse, open the strip, take and put items, and read the frame lines.

## Repair

The container data, owners, item records and item pictures come from small per-room and per-cell tables loaded with the
area (id1/areas.awa), so opening the strip, a take and a put read no file.

## Verification

Measured on FS-UAE at 32 MB Fast in Arrille's Tradehouse: the open took about 0.8 s before and 1 ms now; each take and
the put 0 ms (under 100 ms before). The tradehouse's table is 35,883 bytes and loads in about 40 ms with the room;
walking out and back in reads nothing, because the table is kept. No island-wide file was searched in the session.

## Prevention

The frame wait counters show any file time in a frame, and the session lines count the file opens.
