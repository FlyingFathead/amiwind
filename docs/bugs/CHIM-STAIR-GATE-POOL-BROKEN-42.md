_Last updated with AmiWind v0.0.43-dev3 (18 October 2026)._

## Symptom
The vivec-palace MiniWind (eb7fad7) stopped in its chim stage after 23 minutes: the stair gate walked the whole
Vivec frame (83,236 steps and ramps, 29 walk units on 8 workers; the walker code had changed, so nothing was
reused) and one worker process ended abruptly (`BrokenProcessPool`).

## Where
`tools/chim/collision.py` `stair_gate` (through `build_parallel.completed_map`), chim stage.

## How it happened
Cause not measured yet. The host was short of memory that hour (the Docker VM had an out-of-memory event at
00:00 the same night; the build container had 30 GiB) and a killed worker gives exactly this error. The log does
not name the unit the worker held.

## Why it was not caught
A killed worker names no unit and no memory figure; the stage log ends with the pool's traceback only.

## Reproduction
Run 2026_10_17_v0.0.42-dev1_miniwind-vivec-palace-vivec-in-his-palace-seyda-carrier-fix_eb7fad7, log 23-chim.log.

## Repair
Pending (owner of the stair walk code): name the unit and its peak memory when a walk worker dies, and size the
walk pool by memory as well as by cores. Workaround for a sandbox: `--stair-walk flights` (the gating steps only).

## Verification
Pending.

## Prevention
Every worker pool of a stage names the unit a lost worker held (the verbose-logs rule).
