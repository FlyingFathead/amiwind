_Last updated with AmiWind v0.0.41 (16 October 2026)._

## Symptom

The full v0.0.39-rc1 build stops before world scenery with
`TypeError: unhashable type: 'list'`. The image is not assembled.

## Where

`tools/exterior_plan.py`, `classify_regions`, called by `verify_stage` before
world scenery and flora conversion.

## How it happened

The terrain planner supplies a set of coordinate tuples. The subsequent
stages read the checklist from JSON, where coordinates are lists. The same
selection comparison attempted to put those lists directly into a set.

## Why it was not caught

The tests checked tuple selections and omission of town-owned BSP maps, but
did not run the scenery/flora verification through a serialized checklist
with a nonempty regional CHIM selection. The full build caught it before
scenery conversion or image assembly.

## Reproduction

Write a checklist containing at least one `chim-region` cell to JSON, write
the corresponding terrain receipt, and invoke `verify_stage` on those files.

## Repair

Normalize coordinate pairs to tuples for the selection comparison. Keep
the source checksum, full cell inventory and per-map ownership checks.
No BSP fallback or duplicate compilation is introduced. This is an offline
builder repair; the AmiQuake engine and runtime routing are unchanged.

## Verification

The new regression reproduced the exact TypeError before the repair. After
the repair, all 21 world-manifest tests pass. The disk-round-trip test also
rejects a changed CHIM assignment and mismatched selection. Complete image,
package readback and target checks remain pending.

## Prevention

Exercise serialized stage boundaries using nonempty CHIM selections, in
addition to the planner's in-memory tuple inputs. Keep ownership failures
fatal before conversion.
