## Status: 11 October 2026

Repaired in source on branch v0.0.36-chimport-x; build verification pending. Persisted through v0.0.36-dev2,
-dev3 and -dev4: every one of them shipped the same 270 CHIM coast cells.

## Symptom

Of 724 cells CHIMport has converted and passed, the --chim-regions preflight accepts 271 (all 103 seabed cells and
168 land cells) and refuses 454: "its legacy open world is N maps (a divided cell); a CHIM region frame replaces
exactly one open-world map". The tracker listed 3 to 90 legacy maps for the refused cells.

## Where

`tools/chim/regions.py`, preflight: one CHIM region frame replaces exactly one legacy open-world map (in place, same
map name); `tools/prepare_world_regions.py` and `tools/chim/frame_map.py` took one-map cells only.

## How it happened

Two causes. (1) The in-place design keeps the engine's open-world directory, handover and saves unchanged by giving
each cell's frame its legacy map's name; a cell whose legacy world is several maps had no single name to take.
(2) The preflight judged "several maps" by the tracker's `legacy.maps` list, which is not the cell's own maps: it also
names every map whose 896-unit apron holds an object of the cell. Measured on the v0.0.36-dev4 run's world terrain
receipt: 1,076 cells are one map, 316 are 2 x 2 and 12 are 4 x 4, and every map's core lies inside one cell. Of the
621 finished land cells 473 are one map, so about 305 of the refusals were wrong; 148 cells are truly divided.

## Why it was not caught

The first tests used seabed and coastal cells, which the legacy builder kept as one map each, and the tracker's map
list was never compared with the region directory.

## Reproduction

Always: `--chim-regions` with a region name or all regions.

## Repair

At the shared layer, no engine change (docs/BUILD_MANIFEST.md step 2b):

- the preflight no longer refuses by the tracker's map list (only the earlier method, `--chim-region-rows legacy`,
  keeps the one-map check: it copies one legacy map);
- world terrain, scenery and flora make none of a CHIM cell's maps, divided or not;
- the world terrain stage widens the row of the cell's first map (lowest index) to the whole cell and makes the
  other rows aliases with the same origin, core and coverage; the engine takes the first row whose core holds a
  point, so the whole cell resolves to the first map's name and no alias is ever a destination;
- the image installs one frame map under that name, sets the row and its aliases together, records the aliases,
  removes any legacy map or harvest catalogue left under an alias name (recorded) and counts the cell once;
- the border audit measures region frames (`tools/chim/stitch.py audit --regions`).
- two image steps opened a map for EVERY directory row and stopped on the first alias row (no map by design), found
  by the measured builds: the save fingerprint (`build_aga.write_content_fingerprint`, divided-cell test build) and the
  volume packer (`world_volumes.pack`, first coast2 build). Both skip alias rows now (`chim.frame_map.alias_rows`: a
  row whose bytes repeat an earlier row); every other per-row loop either skips owned rows already or reads only the
  directory. Checked on the failed runs' own staged files: 21 map-less rows, all 21 aliases.

## Verification

Tests (tests/test_chim_regions.py `DividedCells`, tests/test_chim_stitch.py `RegionFramesTest`): no legacy map of the
cell is made and no made map's core reaches into it; the engine's lookup finds the frame's row at every sampled point
of the cell and the neighbours' rows outside it; rows that do not tile the cell are refused; one frame map for a 2 x 2
cell, all four names owned, the cell counted once. With the fixed preflight, 661 cells pass (103 seabed, 558 land,
115 of them divided) against 270 in dev3/dev4, for the dev4 towns. To do: a build with divided coastal cells, its
boot smoke and the border audit of those cells.

## Prevention

The preflight's count of refused cells is shown with every CHIM region build; the map count per cell comes from the
region layout, never from the tracker's apron list.
