## Status: 11 October 2026

Open (hold-level). The pool is healed: dev4 wrote these results under the form-2 keys, which have been stable since
c8812db for both passes. A key rule change now keeps the previous rule as a lookup (BUILD-PASS-KEY-OVERBROAD-36), and
in dev4 that carried hidden-surface cull (2,388 of 2,388 maps) and the character head previews (275 of 275).

## Symptom

`2026_10_11_v0.0.36-dev4_full-coast-arena-dev4-meshmethods_d050b6f`: BSP optimizer 16 maps reused, 2,372 prepared;
exterior sky 2,338 maps written again (32 s on 13.7 cores). Every one of the 2,338 distinct inputs already had an entry
from dev3 (`..._compiled-hull_3b5e7a9`) or earlier, and the output SHA-256 dev4 wrote equals that entry's output
in every case.

## Where

The key rules in `tools/pass_cache.py` `source_digest`.

## How it happened

Both passes' worker code is identical in dev3 and dev4. Under today's rule the key is the same at 3b5e7a9 and
d050b6f (optimizer f71ee4e2..., sky c31f8280...). The key rule changed twice in between:

1. 98933e9 keyed both passes by the code their per-map worker reaches instead of the whole module. Nothing looked
   the old entries up.
2. e4213a1 moved to import-time form 2. Its fallback computes the previous rule on today's tree, which finds
   entries written by the same code under the previous rule. It cannot recompute the whole-module digest that
   dev3's tree had.

## Why it was not caught

Each rule change was checked for "an edit elsewhere keeps the key" on the new rule. No check asked whether the
entries in the pool would still be found the first time the new rule ran. The unit reuse audit and per-entry
provenance, which show this, arrived with these builds.

## Reproduction

Change how a pass key is computed (not the pass code), then run the pass on a pool written before the change.

## Repair

- Since e4213a1, every key rule change keeps its predecessor as a lookup (`previous_digests`), so the next rule
  change finds today's entries.
- Entries written by older trees under older rules are not migrated: dev4 has already rewritten them under the
  current keys.

## Verification

- Form-2 digests computed in the builder image over the 3b5e7a9 and d050b6f trees.
- Output SHA-256 compared for all 2,338 inputs of each pass (`image-passes/optimize-world-maps`,
  `image-passes/exterior-sky`).
- dev4's receipts: hidden-surface cull 2,388 hits and 0 misses through the previous-rule lookup.

## Prevention

- A key rule change must keep the previous rule as a lookup and be checked against the pool before it ships.
- The unit reuse audit (`build_profile.py reuse`) runs after every build and flags a cache that recomputes on
  unchanged inputs.
