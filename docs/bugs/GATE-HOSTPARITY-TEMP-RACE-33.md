## Status: 9 October 2026

Repaired in the gate tooling (outside the source tree).

## Symptom

Gate 900 reported a Windows host-parity error that belonged to another gate running at the same time; rerun
alone, it passed.

## Where

The release gate's Windows host-parity step: it ran the host tests and wrote their output to one log file at a
fixed temporary path, then printed its last lines on failure.

## How it happened

Gates run in parallel since the gate queue. Each gate stages its own source and uses its own work folders, but
this one log path was shared, so one gate could read the other's output (or overwrite its own).

## Why it was not caught

The step was written when only one gate ran at a time; the isolation work for parallel gates moved every other
path to a per-gate folder.

## Reproduction

Start two gates whose Windows host-parity steps overlap, one of them failing: the other can show its error.

## Repair

Each gate writes its host-parity log to a file named after its gate number.

## Verification

Gates run after the repair use their own log; gate 1160 ran with it.

## Prevention

Every file a gate writes lives under that gate's own number; shared fixed paths in gate steps are refused in
review.
