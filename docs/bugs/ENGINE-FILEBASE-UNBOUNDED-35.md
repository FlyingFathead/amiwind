## Status: 10 October 2026

Fixed in source on the v0.0.35 line; ships with v0.0.35.

## Symptom

A model or file name with a long base name overwrote memory after the 32-byte hunk tag buffer; a name without a slash made the scan read before the start of the string.

## Where

`engine/aga/src/common.c COM_FileBase`.

## How it happened

COM_FileBase copied the base name with no size limit and searched backwards for a slash without stopping at the start of the name.

## Why it was not caught

The engine came from the original sources, where these paths assumed well-formed input; no test fed them bad or unusual values.

## Reproduction

Found by reading the source (v0.0.35 engine review).

## Repair

COM_FileBase scans forward for the last slash and dot and writes at most COM_FILEBASE_SIZE (32) bytes, the size of every buffer it is given (hunk tags, model load names).

## Verification

Native fixture: normal names, a name without a slash, an empty base and a 40-character base that is cut to 31 characters with the bytes after the buffer untouched (tests/test_engine_review_native.py).

## Prevention

Untrusted input and unusual values are checked where they enter the engine; each fix has a regression check.
