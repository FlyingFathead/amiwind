## Status: 9 October 2026

Open. The worker pool is not wrong; the test needs a repair.

## Symptom

Gate 1051 failed `test_processes_keep_order_and_limit_nested_threads`: all nine results came from one worker
process ("1 not greater than 1"). The same head passes 3 of 3 runs of the module alone.

## Where

`tests/test_build_parallel.py`. The test maps nine short items (20-60 ms each) over a three-process pool and
expects more than one process to have done work.

## How it happened

The gate ran while builds and other gates used every core. When the other two pool processes start late, the
first one can finish every short item before they ask for work, so only one process id is seen.

## Why it was not caught

The test was written and gated on a quieter host. It is a sibling of TEST-COST-ORDER-LOAD-33 (same cause:
timing on a shared host read as the pool's behaviour).

## Reproduction

Run the full suite while every core is busy; rerun the module alone and it passes.

## Repair

Pending: the test should check what the pool was asked to do (worker count, item order, per-worker thread
limits) without depending on how the host schedules process start-up.

## Verification

Pending.

## Prevention

Scheduler and pool tests check recorded decisions, never timings or process start order of a shared host.
