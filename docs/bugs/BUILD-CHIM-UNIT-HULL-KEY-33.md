## Status: 9 October 2026

Fixed in source on the v0.0.33 integration line, with regression tests.

## Symptom

A development build with `--model-hull chain`, made to test whether the routed standing hulls caused
CHIM-BALMORA-RING-OVER-33, reused all 692 CHIM model-variant units of the previous build (routed hulls)
and failed the heap gate with exactly the same figure.

## Where

`tools/chim/units.py`: the fingerprint of a CHIM build unit hashes its inputs, the sources in `TOOLS`
and the build switches in `SWITCHES`.

## How it happened

The standing-hull form is read from the environment (`AMIWIND_MODEL_HULL`, set from `--model-hull`) by
the converter, and the routing code lives in `tools/routed_hull.py`; neither was part of the unit
fingerprint when the routed hulls were added.

## Why it was not caught

The routed hulls were tested on fresh conversions; no test checked that changing the hull form changes
the unit fingerprint.

## Reproduction

Build the CHIM world once with `--model-hull auto`, then again with `--model-hull chain` in the same
workspace: every variant unit is reused.

## Repair

`AMIWIND_MODEL_HULL` is a unit switch and `tools/routed_hull.py` is a fingerprinted source of mesh and
variant units. The first build after the change converts every unit once.

## Verification

`tests/test_chim_format.py`: toggling the hull form changes the mesh and variant fingerprints, and the
routing source is part of both.

## Prevention

Every environment switch a converter reads belongs in `SWITCHES`; the tests list them.
