## Symptom and reproduction

Convert a CHIM world containing only terrain and water, then run validation
and statistics. Structural checks finish, but measurement calls max() on the
empty scenery-model list and raises ValueError before the remaining gates.
Five original ocean cells exposed this during dev2 preparation.

## Cause and why it escaped

The reporting function assumed at least one scenery model. Existing statistics
fixtures contained scenery, while ocean source tests did not run the complete
post-conversion reporting path. This is a reporting defect, not evidence of a
terrain, water or collision failure.

## Repair

Represent the absent largest model as null. Keep real zero model byte counts,
terrain measurements and all structural, memory and collision checks. Do not
invent a dummy model or bypass validation. No runtime loader changes are needed;
the existing AmiQuake world graft and CHIM terrain loader already admit terrain.

## Verification and prevention

An asset-free terrain world reproduced the exception with both inline terrain
and shared terrain references. Both controls now pass through validation,
measurement and full statistics; all ten statistics tests pass. The existing
invalid-world rejection test also remains passing. The five existing ocean
frames now pass structural validation, statistics, active-ring heap budgets
and zone-allocator walks. The stair gate passes with zero stairs present,
which does not establish in-game collision. Original failed validation is
preserved; geometry was not regenerated or stripped. Runtime routing, native
seams and final-package checks remain pending. Retain both empty-world controls.
