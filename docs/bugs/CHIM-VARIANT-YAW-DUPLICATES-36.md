## Status: 10 October 2026

Open; fixed in source (model weld `base`, the default), not in a numbered build yet. Found by the variant audit
(`tools/chim/variant_audit.py`) while measuring [CHIM-STRIDER-SCALED-SEAMS-36](CHIM-STRIDER-SCALED-SEAMS-36.md).

## Symptom

The v0.0.36-dev3 world holds 253 model records (5,152,512 bytes, 70 meshes) whose name ends in `#2` up to `#49`:
the same variant (mesh, scale, tilt) stored again because its bytes differ from the first one's. The differences
are in the last bits of plane, texture-vector and vertex values (58 records: planes and texture vectors only;
54: planes only; others also vertices or the collision nodes), e.g. `i/in_cave_plant00@s2` stored 49 times and
`f/flora_kelp_03` 45 times across the CHIMport region frames. Nothing looks different. 202 of those records
(4,414,296 bytes) are the yaw's rounding alone (the same faces, edges and texture list, vertices within 0.001 units
of the first copy); the other 20 differ for other reasons (another converter profile,
[CHIM-MESH-PROFILE-SPLIT-36](CHIM-MESH-PROFILE-SPLIT-36.md), or a tilt). No frame's peak memory ring holds two
copies of one variant, so the waste is disk and build time (the same variant unit rebuilt per frame), not ring
memory.

## Where

`chim.models.variant_unit`: the variant is built from the first placement of it in each frame
(`chim.build.frame_input`), through `prepare_mesh_bsp._prepare_placement`, which turns the mesh by the
placement's rotation and back by its yaw. For an untilted variant the yaw belongs to the entity and is not part
of the variant (`prepare_mesh_bsp._instance_key`), but the record was still built at that placement's yaw: the
rotation and its inverse do not cancel exactly in floating point, so each yaw leaves its own rounding in the
record. Two frames whose first placements are turned differently write two records. The variant unit key also
held the yaw, so the unit cache rebuilt the same variant for every frame.

## How it happened

The CHIM model builder took the legacy converter's placement transform as it is; the legacy region maps never
compared one model's bytes between maps, so the yaw's rounding never mattered there. The world writer stores a
model once per content (SHA-256) and names a second content under the same name `#2`, which made the duplicates
visible but did not flag them.

## Why it was not caught

Nothing compared records that carry the same variant name; the validator only checks that no content is stored
twice, and these contents differ in their last bits.

## Reproduction

Always: `tools/chim/variant_audit.py <chim world>` or any listing of the world's model names (names with `#`).

## Repair

`chim.models.variant_ref`: an untilted variant is built at yaw 0 (with the default model weld `base`), so its
record no longer depends on which placement a frame meets first, and its unit key no longer holds that yaw (one
unit for every frame). Tilted variants keep their yaw (it is part of the variant). Measured on the strider: with
the earlier method three yaws at scale 1 gave three different records; now one, the same as the earlier
record at yaw 0. `--chim-model-weld placed` keeps the earlier method.

## Verification

- Unit test (`tests/test_chim_variant_weld.py`): one record for four yaws at three scales; the earlier method gives
  several.
- To do: the next built world has no `#` names from yaw alone (the variant audit lists the rest).

## Prevention

The variant audit runs in the CHIM validator over every baked variant and reports every variant whose shape or
topology differs from its mesh's base.
