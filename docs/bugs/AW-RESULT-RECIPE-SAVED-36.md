## Status: 11 October 2026

Fixed in source on v0.0.36-integration-r1, with a regression test. Not shipped at the time of writing.

## Symptom

After the first Vivec stage A build failed, `aw request` ended with a traceback:
`aw-result-1 document does not validate: $.recipe: unexpected 'saved'`; no result document was written.

## Where

`tools/aw_service.py` `finish_build`: the internal `saved` field of the recipe block was removed
only for a passed build.

## How it happened

The recipes work added `saved` (the recipe the build wrote) for passed builds; a failed build from
a requested recipe (every MiniWind preset) kept the field.

## Why it was not caught

The failed-build test used no requested recipe.

## Reproduction

A failed `aw request --kind miniwind --preset ...` build.

## Repair

`saved` is always removed from the recipe block; it is used only for a passed build.

## Verification

`tests/test_build_recipe.py` `test_a_failed_build_from_a_requested_recipe_writes_a_valid_result`
(fails before the repair, passes after).

## Prevention

The test covers a failed build from a preset recipe.
