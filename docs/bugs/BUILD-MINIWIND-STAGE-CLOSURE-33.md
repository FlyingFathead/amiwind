## Status: 9 October 2026

Fixed in source on v0.0.33-direct-start, not shipped at the time of writing. Found while
merging the quick test build options onto the MiniWind line; the test fails on
v0.0.33-miniwind-ext 1120d84 itself, before that merge.

## Symptom

`tests/test_build_cache.py`, `test_real_stage_closures_leave_engine_sources_to_the_engine_and_image`,
fails: the input fingerprint of `prepare_world_scenery.py` (and of every stage that imports
`tools/build_parallel.py`) covers every file of `engine/aga/src/`.

## Where

`tools/build_parallel.py`, `stage_dependencies`: for a MiniWind plan it imports
`tools/miniwind.py` (`DEPENDENCY_OVERRIDES`, `IMAGE_AFTER`, `omitted`). The stage cache follows
every import of a stage's code, also imports inside functions, so `miniwind.py` and what it
imports (the CHIM builder modules, `project_version.py`, `build_aga.py`) join the closure of
every conversion stage, with the engine source folder they name.

## How it happened

The scheduler needs the MiniWind plan's dependency changes, and the easiest way to reach them
was to import the module that defines them. The scheduler module is imported by the stage code
itself (the shared worker pool), so its imports count for every stage.

## Why it was not caught

The cache test that guards the closures runs in the full suite of the MiniWind line; the gate of
the commit that added the import was not run on that line's merged head, or the failure was not
read.

## Reproduction

On v0.0.33-miniwind-ext 1120d84, run
`python -m unittest test_build_cache.FingerprintTests.test_real_stage_closures_leave_engine_sources_to_the_engine_and_image`
from `tests/`.

## Repair

The MiniWind stage table (`OMITTED`, `SCOPE_OMITTED`, `DEPENDENCY_OVERRIDES`, `IMAGE_AFTER`,
`omitted`) moved to `tools/miniwind_plan.py`: pure data without imports, re-exported by
`tools/miniwind.py`. The scheduler imports only that module, so the closure of a conversion
stage gains one small data file instead of the MiniWind and CHIM builder code.

## Verification

The cache test above passes on v0.0.33-direct-start; the MiniWind plan tests
(`tests/test_miniwind.py`) are unchanged and pass.

## Prevention

The cache test already guards it; the merged head of every line gets the full gate before builds.
