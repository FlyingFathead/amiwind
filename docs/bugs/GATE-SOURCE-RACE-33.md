## Status: 9 October 2026

Open. Found during the v0.0.33-dev1 integration.

## Symptom

Gate 443 reported "dirty 0" for v0.0.33-dev1-build f13c496, then failed 16 bug tracker tests: its
staged `docs/bugs/bugs.json` held merge conflict markers that the commit does not have.

## Where

The local gate runner: it records the head and the dirty count first, then copies the working tree
(about 20 s) into its own staged source.

## How it happened

A merge was being resolved in the same worktree while the gate copied it. The clean check ran
before the copy, so the half-merged files were staged and tested under the clean commit's name.

## Why it was not caught

Nothing compares the staged source with the commit named in the gate header.

## Reproduction

Start a gate on a clean worktree, then edit a tracked file within its first 20 seconds.

## Repair

Not done (queued as a gate tooling item): stage from the committed HEAD named in the header (git
archive), or check after the copy that the tree is still clean and identical to that HEAD, and
refuse the gate otherwise.

## Verification

Pending. Gate 444 on the untouched tree (f95cf75) passed in full.

## Prevention

A gate tests exactly the commit it names.
