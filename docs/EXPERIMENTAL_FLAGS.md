# Experimental flags

_Last updated with AmiWind v0.0.47-dev2 (21 October 2026)._

Work that is in the source but not finished, or not yet the default, ships behind a switch that is
off by default. A default build is unchanged by everything on this page; each switch has a test that
checks it is off by default.

| Switch | Where | Default | What it does | State |
| --- | --- | --- | --- | --- |
| `--skip-census` / `aw_skip_census 1` | builder / engine cvar | off | Quick test builds: New Game skips the Census and Excise Office and opens a quick character screen instead | experimental, unfinished (the screen, its console command and its docs are in progress) |
| `--chim-lighting-type hybrid` | builder | hybrid | CHIM lighting: light styles and the night lamp table widened to every class | partial: terrain lightmaps, model light levels and plant glow not yet |

| `--npc-lod on` (config `npc_lod`) | builder | off | Near and far NPC models chosen by distance (engine `dbg npclod`) | experimental: to be compared in game before it becomes the default |
| `--anim-kit off` / `aw_animkit 0` | builder / engine cvar | on | The previous idle-only residents (the kit is the default) | the old method, kept selectable |

| `--npc-head-detail original` (config `npc_head_detail`) | builder | off (auto = budget) | NPC heads keep every original triangle | experimental: unfinished head/body balance, not yet compared in game |

| `--npc-models parts` | builder | whole | NPC gallery models composed from a shared parts library (each body part converted once) | experimental: joint seams and head spikes still open (NPC-JOINT-GAPS-33, NPC-GALLERY-SPIKE-33) |
| `--night-lamp-lightmaps on` | builder | off | baked night-lamp light (lightstyle 32) on the terrain and buildings of the rebuilt legacy Balmora cores, from `tools/lamp_lightmaps.py` | prototype from v0.0.31 development: untested in a full build; the shipped night lamps stay the engine lights |
| `--file-aliases off` | builder + engine | on | Every byte-identical copy of a model, sound, sprite or tag stored under each of its names on the boot disk; the default stores each once, their other names in `id1/file-aliases.txt`, which the engine's file search reads ([PAYLOAD_SHARING.md](PAYLOAD_SHARING.md); about 21 MB less on the v0.0.46 payload) | the old method, kept selectable; `on` is the default since v0.0.47 (decided for the project, 2026-10-21; v0.0.47-dev2 was built with it) |
| `--shared-skins off` | builder + engine | on | Every actor model keeps its own copy of a skin that several actor models repeat; the default stores it once in `progs/skins/`, the models pointing to it ([PAYLOAD_SHARING.md](PAYLOAD_SHARING.md); about 65 MB less on the v0.0.46 payload) | the old method, kept selectable; `on` is the default since v0.0.47 (decided for the project, 2026-10-21; v0.0.47-dev2 was built with it) |
| `--chim-terrain-hull auto` / `--chim-terrain-refs off` | builder | compiled / on | CHIM chunk terrain the earlier way: routed hull chains for the regular grid and a terrain copy in every chunk (world format 0.5); the defaults since v0.0.36 are the compiled hull (checked and patched against its pieces) and terrain references (format 0.7) | the old method, kept selectable: a default build with it overruns Balmora's CHIM ring (CHIM-BALMORA-RING-GROWTH-36) |
| `--chim-model-hull-patch off` | builder | on | Compiled model hulls stay exactly as compiled (the check is still recorded); the default adds back the pieces the compiler lost under a walkable surface | the old method, kept selectable (CHIM-COMPILED-HULL-SHORT-36) |
| `--chim-model-hull-patch on` | builder | off | Compiled model hulls get the pieces the compiler lost under a walkable surface added back exactly | experimental: makes 11 Balmora and test-area models exact, but Balmora's ring has no zone room for it yet (CHIM-COMPILED-HULL-SHORT-36) |
| `--chim-placement-format 0.8` (`chim_build.py --placement-format`) | builder (+ engine: reads 0.4 to 0.8) | 0.7 | CHIM world format 0.8: one model per mesh and scale, the whole rotation in a 56-byte placement record, collision from the mesh's own convex pieces expanded by the world-aligned player box when a trace meets them ([world format](chim/WORLD_FORMAT.md#placed-models-08-experimental)) | experimental: host tests only, no build or in-game look yet; estimated on the v0.0.46 world 32,714 models to 8,105 and about 455 MB less model and record bytes (CHIM-TILT-VARIANTS-SPLIT-33) |
| `--chim-reach-index refs` (`chim_build.py --reach-index`) | builder (+ engine: reads 0.4 to 0.9) | copies | CHIM world format 0.9 (needs `--chim-placement-format 0.8`): a chunk that a placement's drawn box reaches but does not own holds a 4-byte reference to the owner record in the same frame instead of a whole copy ([world format](chim/WORLD_FORMAT.md#reach-index-09-experimental)) | experimental: host tests only, no build or in-game look yet; estimated on the v0.0.46 world placement records 60.9 MB to 28.8 MB against format 0.8, and more reads per chunk load when the owner chunk is not in the zone (CHIM-PLACEMENT-MARGIN-COPIES-46) |
| `--chim-actor-table off` (`build_aga.py image --chim-actor-table`; engine: `chim actors table 0`) | builder + engine | on | No actor table and no actor library stage: only the frame maps place actors. The default ends `id1/default-game.cfg` with `chim actors table 1` (the engine's own setting is off and not saved) and writes every exterior NPC and creature reference of the game data to `maps/chim-actors.cca`, outside the frames; the type 1 window takes a joining frame's actors from it ([world format](chim/WORLD_FORMAT.md#actor-table-experimental)); version 2 (v0.0.47) adds the levelled creature lists, rolled at the player's level when a cell joins and kept in the change list (`chim actors seed N` sets the session seed); its change list (picks, deaths, moved and fighting actors) goes into saves as AWS4 feature 8 (a save without it is the same bytes as before) | the old method, kept selectable; `on` is the default since v0.0.47 (decided for the project, 2026-10-21; v0.0.47-dev2 was built with it); 5,981 references, about 200 KB on the v0.0.46 data (CHIM-EXTERIOR-ACTORS-MISSING-46) |
| `tools/creature_library.py` and `tools/npc_library.py` (the actor library stage, `tools/actor_library.py`: in every build with the actor table, the default since v0.0.47) | builder | run by a default build | Models per creature mesh, keyed by the mesh instead of the record: method `kf` (default of the library) poses the creature's animated model with its keyframe files as the original reads them (`tools/creature_pose.py`): a standing model (idle, hit, death: 16 frames) and a mover model (idle, walk, run, attack, hit, death: 38 frames); method `resident` is the resident stage's 8-frame idle bake; plus the creature bases' entity text for the actor table, at the instance scales the exterior uses | experimental: host tests; measured read-only on the game data, all 39 exterior creature meshes bake with `kf` (25 with `resident`; CREATURE-BAKE-NIF-UNSUPPORTED-47); the NPC standing library adds one standing model per appearance for the exterior NPCs outside the CHIM towns (the resident bake's animation kit branch, no mover, items or voice); the engine draws a live actor at its instance scale, so scaled creature models are optional (`--scaled-variants`) |
| `--chim-crossing 0` (`build_aga.py image --chim-crossing`; engine: `chim crossing 0`) | builder + engine | 1 | The image starts with type 0 cell crossings (a level change at every frame border): nothing written. The default ends `id1/default-game.cfg` with `chim crossing 1`, run before any map, so the game starts with type 1 crossings; towns never join a type 1 window and keep type 0 crossings in either case ([cell crossings](chim/CELL_CROSSINGS.md)); `chim crossing 0` in the console before a map starts gives type 0 back | the old method, kept selectable; type 1 is the default since v0.0.47 (decided for the project, 2026-10-21; v0.0.47-dev2 was built with it) |
| `--chim-terrain-pack bsp29` / `compact` (`chim_build.py --terrain-pack`) | builder (+ engine: reads 0.4 to 0.11) | generate | `bsp29`: CHIM terrain records as BSP29 brush images (the method before); `compact`: world format 0.10, a terrain record stored as a lossless repack the engine expands to the same BSP29 bytes before loading it ([world format](chim/WORLD_FORMAT.md#compact-terrain-records-010-experimental)). The default `generate` (world format 0.11) stores a regular-path terrain record as its corner heights and the facts the builder decided, a record of the converter's own triangles as its 32-unit samples and the triangles; the engine generates its render part, the same BSP29 bytes, before loading it (planes and the standing hull stay stored); every other record as `compact` ([world format](chim/WORLD_FORMAT.md#generated-terrain-records-011-experimental)); `compact` and `generate` need `--chim-terrain-refs on` (with `off` the builder keeps `bsp29`) | the old methods, kept selectable; `generate` is the default since v0.0.47 (decided for the project, 2026-10-21; v0.0.47-dev2 was built with it); measured on the v0.0.46 world, terrain records 489.4 MB to 247.6 MB (`compact`: 450.8 MB), 95,818 of 97,369 generated byte for byte |
| `--chim-model-bevels exact` or `tol:N` | builder | profile | Every CHIM model's standing hull gets edge bevels: all of them (exact), or those whose omission lets the hull reach more than N units past the exact expansion | experimental: removes the solid the bevel-less expansion adds beside rocks (up to 82 units), but the bevels' planes do not fit the CHIM zone at the heaviest frames (CHIM-COMPILED-HULL-OVERFILL-46) |
| `--coord-range narrow` (`AW_COORD_NARROW`, `make EXTRA_DEFINES=-DAW_COORD_NARROW`) | builder / engine compile switch | wide | Positions travel as Quake's 16-bit eighths (about +/-4,096 units, protocol 15) instead of the default 24 bits of 1/256 units (+/-32,768, protocol 1015, one byte more per coordinate); the frame, arrival and spawn bounds follow (`AW_COORD_BOUND`, engine/aga/src/aw_coord.h; builder tools/coord_range.py; audit list config/coord-range-audit.json); an area wider than +/-4,000 (all of Vivec in one frame, `vivec_city`) is refused | the old method, kept selectable (CHIM-FRAME-COORD-RANGE-33); `--engine-experiment widecoord`, the switch of the v0.0.36 spike, still selects wide |
| `--engine-profile upstream` (`--engine-asm`, `--engine-opt`) | builder (`build.py`, `build_aga.py engine`) | c | The engine compiled with the optimisations of TerribleFire's AmiQuake GCC port (Stephen Leary), including NovaCoder's original routines: upstream's 68k assembly for the turbulent span loop and the chunky-to-planar conversion, at `-O1` as upstream builds; `--engine-opt o2` is the selective `-O2` experiment ([engine profiles](ENGINE_PROFILES.md)) | experimental: measured on the slow preset before the maintainer picks the default; `c` stays the regression reference build |
| `--stair-walk-cache full` | builder | records (cached with `--developer-mode`) | Walks every map and CHIM frame again instead of reusing the stored walk of unchanged ones | regression and beta-test runs only (from-scratch reference build, nightly check) |
| `--collision-underside rule` / `split` / `whole` | builder | names | A general rule instead of the list of mesh names (the two Velothi temples) that keep their authored collision under a slab: a convex piece filling more than a unit under an authored downward-facing surface becomes authored plates (`rule`), is split first (`split`), or its whole mesh keeps its authored surfaces (`whole`). Measured on every exterior mesh: `rule` +33 % standing clip nodes and the Vos walkway step still starts in solid; `whole` lets it pass but doubles the clip nodes (CHIM-VOS-TEMPLE-WALKWAY-41) | experimental: measurement and A/B builds only |
| `--stair-collision-method 1` | builder | 0 | A stairway collision mesh for each flight of stairs whose collision fails the geometric stair check (the standing box over every tread and across every seam, plane arithmetic, no walk): one ramp per run of steps or one solid block per tread, walkways (rope bridges, docks) as sloped plates along their boards; the drawn steps unchanged. A build with it collects the check into its summary and fails on a mesh that fails it. On the v0.0.46 release build's meshes it changes 14 of 97 flight meshes (+11 % collision bytes on them) and cannot yet fix 11; default builds keep their mesh units and keys (CHIM-STAIR-COLLISION-MESH-47) | experimental: measured on meshes only, not in game |
| `--engine-cpu 68060` (`make ENGINE_CPU=68060`) | builder (`build.py`, `build_aga.py engine`) | 68040 | The engine compiled with GCC's 68060 instruction selection (`-m68060 -mhard-float`): no `fscc` and no 64-bit `MULS.L`/`DIVS.L` in the engine code, `FINTRZ` in hardware; it runs on a 68060 only ([68060](68060.md), [engine profiles](ENGINE_PROFILES.md#the-68060-targeted-build)) | experimental: measured before it is offered; the 68040 build stays the baseline and the default |
| `--start-disabled original` | builder | placed | The actors the original's start script disables at a new game (the Dreamers, the Dreamer Prophet, quest characters; read from the game data, `tools/start_disabled.py`) are left out of the resident stages and listed with the condition that enables them ([NPC-STORY-DISABLED-AT-START-42](bugs/NPC-STORY-DISABLED-AT-START-42.md)) | waiting for the runtime enable (the world state's "disabled at start" records): nothing brings a left-out actor back during play yet |

More rows are added as the remaining side branches are gathered into this release.

Five switches left this table as experimental in v0.0.47 and became the default (decided for the project,
2026-10-21: v0.0.47 ships the content of v0.0.47-dev2, which was built with them): `--chim-crossing 1` (type 1
cell crossings), `--chim-actor-table on` (the actor table and the actor library stage), `--chim-terrain-pack
generate` (world format 0.11), `--file-aliases on` and `--shared-skins on`. Their earlier values stay selectable
and are listed above as the old methods; `--public-defaults` refuses them. World format 0.8
(`--chim-placement-format 0.8`) and 0.9 (`--chim-reach-index refs`) stay experimental.

`--chim-native-towns on` left this table in v0.0.36: it is the default (CHIM-native areas: every CHIM area
prepared through the CHIM pipeline from the game data, with no legacy town chain; Seyda Neen too since
v0.0.36-dev5, whose frame maps are made from the scene stage's town with no region maps cut). The
open world outside the town frames was made of legacy region maps until the regional CHIM builds; since v0.0.43
every exterior cell of Vvardenfell is a CHIM frame and no legacy region map is left outdoors.

## Retired flags

A retired flag selects an older method that is kept in the source only for historical regression tests
(`tools/retired_flags.py`). Its help starts with "RETIRED - DO NOT USE except for antiquated regression
testing". In developer mode (`--developer-mode`, used by every development, release candidate and final
build) it stops the build before any stage:

```
ERROR: --legacy-area has been disabled since CHIM v0.1.0 in development mode. Override only if sure / for historical regression tests: --override legacy-area
```

`--override NAME` (repeatable) lets that one flag through. Outside developer mode the build continues with
`WARNING: DO NOT USE <flag> EXCEPT FOR ANTIQUATED REGRESSION PURPOSES (retired since CHIM v0.1.0)`. Every use,
overridden or not, is printed in a `RETIRED FLAGS USED: ...` banner at the start and in the end-of-build
summary, and recorded as `retired_flags_used` in `build-state.json`, `build-summary.json` and the image
receipt `image/build.json`.

| Flag | Override name | Retired since | What it selects | Use instead |
| --- | --- | --- | --- | --- |
| `--legacy-area TOWN` | `legacy-area` | CHIM v0.1.0 | TOWN's CHIM frame prepared through the legacy region-map chain (its region maps built, the frame map copying its actors from them) | the default CHIM-native town |
| `--chim-native-towns off` | `chim-native-towns-off` | CHIM v0.1.0 | every CHIM town prepared through its legacy chain (the v0.0.35 default; Seyda Neen: its region maps cut in the image step) | `--chim-native-towns on` (the default) |
| `--chim-area`, `--miniwind-town` or `--extra-town` naming a Vivec district (`vivec_arena`, `vivec_foreign`, `vivec_hlaalu`, `vivec_redoran`, `vivec_telvanni`, `vivec_temple`, `vivec_delyn`, `vivec_olms`) | `vivec-districts` | CHIM v0.1.0 (retired 11 October 2026) | one CHIM frame per canton (the Arena-only frame of Vivec stage A, or another district) instead of the whole city | `vivec_city`, all of Vivec in one CHIM frame with its rooms (the default) |
| `--seyda-recorded DIR` | `seyda-recorded` | CHIM v0.1.0 (retired 10 October 2026) | the recorded v0.0.31 Seyda Neen region maps shipped instead of Seyda Neen converted from the game data (NOT RECOMMENDED since v0.0.31) | Seyda Neen converted from the game data (the default) |

Not retired, but not recommended: `--seyda-recorded DIR` (the recorded v0.0.31 Seyda Neen maps, NOT
RECOMMENDED since v0.0.31) stays selectable with a loud warning in every mode.
